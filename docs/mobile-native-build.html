Cómo funciona

La app nativa es una cáscara Capacitor que carga tu dashboard desplegado (la web Next.js) dentro de un WebView nativo, más plugins nativos para lo que un navegador no puede hacer bien: push confiable (APNs/FCM), barra de estado tipo glass, splash, y el botón atrás de Android.

apps/mobile (Capacitor) ── carga ──▶ tu dashboard desplegado (server.url) ├─ ios/ (Xcode) + push nativo (APNs vía FCM) └─ android/ (Android Studio) + barra de estado, splash, botón atrás El dashboard trae un "puente nativo" (components/NativeBridge.tsx) que se activa SOLO dentro de la app (Capacitor.isNativePlatform()); en un navegador normal no hace nada.
Por qué server.url y no empaquetar: WABOS es un inbox en vivo — siempre necesita conexión. Cargar la web desplegada significa que cada cambio de la web se publica al instante, sin recompilar ni volver a pasar por revisión de la tienda. Solo recompilas cuando cambian cosas nativas (plugins, permisos, íconos).

1 · Apunta la app a tu dashboard

La app carga la URL que le des en WABOS_APP_URL. Úsala con tu dominio de producción, o con un túnel de Cloudflare para probar (ver la guía PWA).

# Instala dependencias del monorepo si aún no lo hiciste
pnpm install

# Elige a dónde apunta la app (producción o túnel de pruebas)
export WABOS_APP_URL=https://app.wabos.co
# export WABOS_APP_URL=https://<tu>.trycloudflare.com   # para probar
El dashboard y el motor deben estar accesibles por HTTPS desde el teléfono. Igual que la PWA, un http://IP-local no sirve.

2 · Agrega las plataformas nativas

Estas carpetas (ios/, android/) se generan localmente y están en .gitignore por defecto. Desde apps/mobile:

cd apps/mobile

# iOS (requiere Mac + Xcode + CocoaPods)
pnpm add:ios

# Android (requiere Android Studio / SDK)
pnpm add:android

# Copia la config + web a los proyectos nativos
WABOS_APP_URL=$WABOS_APP_URL pnpm sync

pnpm sync es cap sync: reaplica capacitor.config.ts (incluida tu WABOS_APP_URL) y los plugins a ambos proyectos. Ejecútalo cada vez que cambies la config o agregues un plugin.

3 · Corre en un dispositivo

iOS

Abre el proyecto: pnpm open:ios (abre Xcode).
En Xcode, selecciona el target App → pestaña Signing & Capabilities → elige tu Team (tu Apple ID). Xcode genera el perfil de firma.
Conecta un iPhone (o elige un simulador), presiona ▶ Run.
La primera vez en un iPhone físico: en el teléfono, Ajustes → General → VPN y gestión de dispositivos → confía en tu perfil de desarrollador.

Android

Abre el proyecto: pnpm open:android (abre Android Studio).
Deja que Gradle sincronice. Conecta un teléfono con depuración USB activada (o crea un emulador).
Presiona ▶ Run.

Deberías ver WABOS a pantalla completa, cargando tu dashboard, con la barra de estado integrada y el botón atrás de Android funcionando.

4 · Notificaciones push nativas (Firebase)

El push nativo va por Firebase Cloud Messaging (FCM), que entrega a Android directo y a iOS vía APNs. Sin esto la app funciona igual, pero no llegan notificaciones nativas (queda apagado, como la PWA sin llaves VAPID).

a) Proyecto Firebase

Crea un proyecto en console.firebase.google.com.
Android: agrega una app Android con el package co.wabos.app, descarga google-services.json y colócalo en apps/mobile/android/app/google-services.json.
iOS: agrega una app iOS con el bundle id co.wabos.app, descarga GoogleService-Info.plist y arrástralo dentro de apps/mobile/ios/App/App/ en Xcode.
iOS — APNs: en Apple Developer crea una APNs Auth Key (.p8) y súbela en Firebase → Configuración del proyecto → Cloud Messaging → Apple app configuration. En Xcode, target App → Signing & Capabilities → + Capability → Push Notifications (y Background Modes → Remote notifications).

b) Credenciales del motor (envío)

En Firebase → Configuración del proyecto → Cuentas de servicio → Generar nueva clave privada (descarga un JSON). Copia tres valores a apps/engine/.env:

FCM_PROJECT_ID=tu-proyecto           # "project_id" del JSON
FCM_CLIENT_EMAIL=firebase-adminsdk-...@tu-proyecto.iam.gserviceaccount.com   # "client_email"
FCM_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"   # "private_key" (con los \n)

Reinicia el motor. En el arranque registra web push dispatcher started (ahora también cubre FCM). El motor envía a ambos transportes: web-push (navegadores/PWA) y FCM (apps nativas).

No hace falta tocar código del motor: el remitente FCM (modules/fcm.ts) y el almacén de tokens (device_tokens) ya están integrados en sendPush(). El puente del dashboard registra el token del dispositivo automáticamente tras iniciar sesión.

c) Probar

Abre la app, inicia sesión, acepta el permiso de notificaciones. Luego dispara un evento (un cliente escribe, o un comprobante entra a revisión) — debe llegar una notificación nativa. Los eventos que disparan push: mensaje nuevo entrante, comprobante por revisar, y pago confirmado.

5 · Íconos y pantalla de splash

Pon un icon.png (1024×1024) y un splash.png (2732×2732) en apps/mobile/resources/ y genera todos los tamaños:

cd apps/mobile
npx @capacitor/assets generate --iconBackgroundColor '#5b4bff' --splashBackgroundColor '#5b4bff'

El color de marca es Electric Indigo #5b4bff (definido también en capacitor.config.ts para el splash).

6 · Publicar en las tiendas

App Store

En Xcode: Product → Archive → distribuir a App Store Connect.
En App Store Connect, crea la ficha (nombre, capturas, privacidad) y envía a revisión.
Apple exige funcionalidad nativa real (la tenemos: push + integración nativa), así que no cae en la regla “solo una web”.

Google Play

En Android Studio: Build → Generate Signed Bundle / APK → Android App Bundle (.aab) (crea/usa un keystore y guárdalo — lo necesitas para cada actualización).
Sube el .aab en Play Console, completa la ficha y publica.

Solución de problemas

  • La app abre en blanco — WABOS_APP_URL no estaba puesto al hacer pnpm sync, o el dashboard no es accesible por HTTPS. Verás la pantalla de fallback “Configura la URL…”. Reexporta la variable y vuelve a sincronizar.
  • iOS no compila / falta Pods — instala CocoaPods (sudo gem install cocoapods) y corre pnpm sync otra vez.
  • Android: “SDK location not found” — abre el proyecto una vez en Android Studio para que escriba local.properties, o define ANDROID_HOME.
  • No llegan push nativas — confirma: (1) google-services.json / GoogleService-Info.plist en su lugar; (2) capacidad Push + APNs key subida a Firebase (iOS); (3) FCM_* en el .env del motor y motor reiniciado; (4) iniciaste sesión en la app y aceptaste el permiso.
  • El botón atrás cierra la app — es lo esperado en la raíz; dentro de una vista hace history.back().
  • Cambié la web pero la app muestra lo viejo — el WebView cachea; fuerza cierre de la app y reábrela, o despliega con un cache-bust.
