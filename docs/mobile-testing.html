📱 Instalar y probar la app móvil

Cómo instalar WABOS y dejarlo funcionando por completo (incluidas las notificaciones push) en un iPhone y un Android real, antes de publicarlo.

Es una PWA — no se descarga de la App Store ni de Google Play

Léelo primero: la “app móvil” de WABOS es una PWA (Progressive Web App), no una app nativa. No hay nada que descargar de la App Store ni de Google Play. Se instala directamente desde el navegador del teléfono (“Agregar a inicio”). Una vez instalada abre a pantalla completa, con su propio ícono, una barra de navegación tipo glass y notificaciones push — se siente como una app de tienda para el uso diario, pero sin revisión de tienda, sin la cuota de $99/año de Apple y con actualizaciones instantáneas.

Por qué no basta con abrir la IP de tu laptop en el teléfono

Las PWA requieren un contexto seguro. Los service workers (offline + lo que recibe las push) y la API de Notificaciones solo funcionan sobre HTTPS, o sobre http://localhost.

  • En tu laptop, http://localhost:3000 es contexto seguro → todo funciona.
  • En tu teléfono, http://192.168.x.x:3000 no lo es → sin instalación, sin push.

Por eso, para probar en el teléfono necesitas una URL pública HTTPS. Lo más fácil (y ya usado en este proyecto para los webhooks de facturación) es un túnel de Cloudflare: sin cuenta, sin configuración, un comando. Correremos dos túneles: uno para el motor y otro para el dashboard.

Teléfono ──HTTPS──▶ Cloudflare ──▶ tu laptop ├─ dashboard :3000 (la app que instalas) └─ engine :4000 (API + WhatsApp + push)

Prerrequisitos (una sola vez)

  1. Instala cloudflared (omite si ya lo tienes): 
    brew install cloudflared
  2. Genera las llaves de web-push (VAPID) — la push está apagada hasta que existan: 
    cd ~/Desktop/WABOS/apps/engine
npx web-push generate-vapid-keys
    Copia las dos llaves que imprime en apps/engine/.env: 
    VAPID_PUBLIC_KEY=BAbc...           # la "Public Key"
VAPID_PRIVATE_KEY=xyz...           # la "Private Key"
VAPID_SUBJECT=mailto:tu@dominio.com

Paso a paso

Abre cinco pestañas de terminal. Deja cada una corriendo.

Tab 1 — Postgres (arranca primero)

cd ~/Desktop/WABOS/apps/engine && pnpm pg:dev

Tab 2 — Motor (engine)

cd ~/Desktop/WABOS/apps/engine && pnpm dev

Espera API listening on http://localhost:4000.

Tab 3 — Dashboard

cd ~/Desktop/WABOS/apps/dashboard && pnpm dev

Tab 4 — Túnel del motor

cloudflared tunnel --url http://localhost:4000

Imprime una URL como https://cold-lake-1234.trycloudflare.com. Llámala ENGINE_URL.

Tab 5 — Túnel del dashboard

cloudflared tunnel --url http://localhost:3000

Imprime otra URL, p. ej. https://green-sky-5678.trycloudflare.com. Llámala APP_URL — este es el enlace que abres en tus teléfonos.

Apunta la app al túnel del motor

El dashboard (corriendo en tu teléfono) debe alcanzar el motor por su URL pública, no localhost. Edita apps/dashboard/.env.local:

NEXT_PUBLIC_ENGINE_URL=https://cold-lake-1234.trycloudflare.com   # tu ENGINE_URL

Luego reinicia la Tab 3 (el dashboard) para que tome el cambio.

CORS ya es permisivo en desarrollo (el motor deja ALLOWED_ORIGIN sin definir), así que no necesitas configurar nada más para que el teléfono hable con el motor.

Conecta un número de WhatsApp

En tu laptop, abre APP_URL, inicia sesión (o regístrate) y ve a Conexión → escanea el QR desde el teléfono del negocio (WhatsApp → Dispositivos vinculados). Es el mismo flujo de siempre; no cambia para móvil.

Instalar en el teléfono

Android Chrome

  1. Abre APP_URL en Chrome.
  2. Inicia sesión. En un momento aparece el banner “Instalar” de WABOS sobre la barra inferior — tócalo → Instalar. (O usa el menú ⋮ de Chrome → Instalar app / Agregar a pantalla de inicio.)
  3. Abre WABOS desde tu pantalla de inicio — arranca a pantalla completa.
  4. Toca “Notificaciones” en el banner (o el diálogo) y Permitir.

iPhone Safari (tiene que ser Safari, no Chrome)

  1. Abre APP_URL en Safari.
  2. Inicia sesión.
  3. Toca el ícono Compartir (□↑) → baja → Agregar a inicio → Agregar. (iOS solo instala PWA desde el menú Compartir de Safari — el banner dentro de la app también muestra esta pista.)
  4. Abre WABOS desde el ícono de la pantalla de inicio (no desde Safari). Esto importa: iOS solo permite notificaciones para una PWA abierta desde el inicio.
  5. Toca “Notificaciones” y Permitir. (Requiere iOS 16.4 o superior.)

Solución de problemas

  • No aparece “Instalar” / no hay push en Android — no estás en HTTPS. Confirma que abriste la APP_URL (el enlace trycloudflare.com), no localhost ni una IP.
  • El iPhone no ofrece notificaciones — debes (a) estar en iOS 16.4+, (b) haber Agregado a inicio, y (c) abrirlo desde el ícono de inicio. Las notificaciones desde una pestaña de Safari no están soportadas.
  • La app carga pero sin datos / “Request failed” — NEXT_PUBLIC_ENGINE_URL sigue apuntando a localhost, o no reiniciaste el dashboard tras editarlo. Debe ser el túnel ENGINE_URL.
  • Next.js dev bloquea el origen del túnel — si los assets no cargan desde el túnel, agrega el host del túnel a apps/dashboard/next.config.ts: 
    const nextConfig: NextConfig = { allowedDevOrigins: ['*.trycloudflare.com'] };
    y reinicia el dashboard.
  • Cambiaron las URLs del túnel — cloudflared genera una URL nueva en cada reinicio. Si reinicias la Tab 4 o 5, actualiza NEXT_PUBLIC_ENGINE_URL (y vuelve a abrir la nueva APP_URL en los teléfonos).
  • La push sigue en silencio tras activarla — confirma que las llaves VAPID están en apps/engine/.env y que reiniciaste el motor. Al arrancar, el motor registra web push dispatcher started (bien) o web push not configured (faltan llaves).
  • Versión vieja atascada en el teléfono — un service worker cachea el shell. Desliza para refrescar, o desinstala y vuelve a agregar a inicio, para forzar la actualización.

Ir a producción (más adelante)

Para usuarios reales no usas túneles — despliegas:

  • Dashboard → Vercel (Next.js estático). Pon NEXT_PUBLIC_ENGINE_URL al dominio HTTPS público del motor y reconstruye.
  • Motor → un host persistente (Render/Railway/Fly/VPS) — no serverless, porque mantiene sockets de WhatsApp (Baileys) de larga vida. Define ALLOWED_ORIGIN al dominio del dashboard, más las mismas VAPID_* y DATABASE_URL que usas ahora.

Ambos deben ser HTTPS (lo serán por defecto en esas plataformas), así que la instalación + push funcionan igual que a través del túnel.
