Cómo poner WABOS en vivo con Docker. Empieza leyendo Cómo funciona y Costos & producción para el panorama (qué corre hoy en la Mac vía túnel, qué cuesta, y el salto a un VPS 24/7). Cómo funciona (y cómo funcionará)

AHORA WABOS está corriendo en la Mac del dueño con Docker, y sale a internet por un túnel de Cloudflare — sin abrir puertos, sin IP pública, con HTTPS real en https://wabos.bouldhq.com. El hermano lo abre desde su teléfono como cualquier web/PWA.

Teléfono del hermano
      │  https://wabos.bouldhq.com
      ▼
Cloudflare (HTTPS + CDN)          ← termina el TLS, edges en Lima/Santiago
      │  túnel cifrado (cloudflared, servicio launchd)
      ▼
Mac del dueño  ── Caddy :80 ─┬─ /api  /ws ─▶ engine (Fastify + WhatsApp + workers)
                             └─ resto     ─▶ dashboard (Next.js)
                                             engine ─▶ Postgres (contenedor, volumen pgdata)

Todo vive en contenedores Docker: postgres, engine (API tienda + WhatsApp + IA + workers), dashboard (la UI), web (marketing) y caddy. La sesión de WhatsApp y los datos se guardan en volúmenes que sobreviven reinicios.

Límite de este modo: la Mac debe estar encendida, despierta y con internet. Si se duerme o se cae el WiFi, WABOS deja de responder y WhatsApp puede desvincularse. Es un puente perfecto para arrancar sin gastar — no es 24/7 de verdad.

DESPUÉS El salto a “producción de verdad” es el mismo Docker pero en un VPS (un servidorcito Linux siempre encendido) con un dominio. Ahí Caddy saca su propio HTTPS y ya no hace falta el túnel ni la Mac. Cero reescritura: es copiar el repo, el .env, y docker compose up -d.

Qué hacer cuando haya plata (pasar a 24/7)

  1. Rentar el VPS (Hetzner CX23, Ubuntu) e instalar Docker — ver la Ruta rápida: Hetzner y §2.
  2. Apuntar el dominio al VPS (registro A). Puede ser el mismo wabos.bouldhq.com o uno propio de WABOS.
  3. Copiar el repo + el .env al servidor (rotando los secretos y la key de Anthropic), poner APP_DOMAIN=tudominio, y docker compose up -d --build. Caddy saca el HTTPS solo.
  4. Mudar los datos de la Mac al VPS con un backup de Postgres (ver abajo) — o empezar limpio si aún no hay data real.
  5. Apagar el túnel de la Mac (launchctl unload ~/Library/LaunchAgents/com.wabos.cloudflared.plist) y listo: ya no depende de tu computadora.

Cómo seguir trabajando mientras tanto

  • Mantén la Mac despierta y enchufada (System Settings → Pantalla → no dormir; laptop con tapa abierta).
  • Docker Desktop: activa “Start when you sign in” — los contenedores se auto-reinician (restart: unless-stopped).
  • El túnel se auto-levanta (servicio launchd); no hay que tocarlo.
  • Haz backups (siguiente punto). Es lo único que no se recupera solo.

La base de datos (dónde vive y cómo respaldarla)

Postgres corre en el contenedor postgres y guarda todo en el volumen pgdata — sobrevive reinicios y actualizaciones. La sesión de WhatsApp vive en wa_auth y los medios en wa_data.

Backup (hazlo seguido):

# Vuelca toda la base a un archivo con fecha
docker compose exec postgres pg_dump -U wabos wabos > wabos-$(date +%F).sql

Restaurar (o mudar al VPS): copia ese .sql al otro equipo y:

cat wabos-2026-07-30.sql | docker compose exec -T postgres psql -U wabos wabos
Cuando quieras dejar de preocuparte por la base, apunta DATABASE_URL a un Postgres manejado (Neon o Supabase, tienen plan gratis) y quita el contenedor postgres — ellos hacen los backups por ti. Es cambiar una línea del .env.

★ Ruta rápida: Hetzner + un subdominio que ya tienes

Esta es la ruta usada para el primer lanzamiento. No hace falta comprar un dominio nuevo: se usa un subdominio de uno que ya controlas (p.ej. wabos.tudominio.com), y Caddy le emite HTTPS real automáticamente — necesario para la PWA (notificaciones push, instalar la app, login con Google).

  1. Servidor: Hetzner Cloud → nuevo CX23 (2 vCPU / 4 GB), imagen Ubuntu 24.04, región más cercana a tus usuarios (Ashburn ash es la de menor latencia para Perú). Agrega tu llave SSH. Anota la IPv4 pública.
  2. Subdominio: en el DNS del dominio que ya controlas, agrega un registro A: wabos → <IP de Hetzner>.
  3. Sigue desde §2 (instalar Docker) en adelante, usando APP_DOMAIN=wabos.tudominio.com.
⚠️ Si ese dominio está en Cloudflare, pon este registro como DNS only (nube gris), no proxied — para que Caddy pueda completar el desafío de Let's Encrypt y el WebSocket /ws pase limpio.
Cuando tengas el dominio dedicado (el próximo mes): agrega su registro A, cambia APP_DOMAIN, ALLOWED_ORIGIN y DASHBOARD_URL en .env, y corre docker compose up -d. Caddy emite el nuevo certificado en la primera visita — sin reconstruir.

0 · Qué necesitas

  • Un VPS (2 vCPU / 2–4 GB RAM alcanza para empezar) con Ubuntu 22.04+ — p.ej. Hetzner, DigitalOcean, Vultr. Necesitas acceso SSH como root/sudo.
  • Un dominio que controles (p.ej. app.tudominio.com) para que Caddy emita el certificado HTTPS. No es estrictamente obligatorio para una primera prueba (puedes usar HTTP plano sobre la IP), pero muy recomendable.
  • Una API key de Anthropic para el Empleado IA (opcional — sin ella la app igual funciona, las conversaciones quedan en modo manual/humano).
  • Un bucket de Cloudflare R2 para las fotos de productos (opcional — el catálogo y el import/export CSV funcionan sin él; solo la carga de fotos lo necesita). Ver §6.
⚠️ Rota los secretos primero. El apps/engine/.env local ha contenido claves reales durante el desarrollo (Anthropic, Lemon Squeezy). Antes de salir en vivo, regenera esas claves en el panel de cada proveedor y pon solo las nuevas en el .env del servidor. Nunca reutilices una clave que estuvo en un árbol de trabajo.

1 · Apuntar el DNS al servidor

En tu proveedor de DNS, crea un registro A:

app.tudominio.com   →   <IP pública de tu VPS>

(Si además servirás el sitio de marketing, agrega otro registro A para él.) El DNS puede tardar unos minutos en propagarse.

2 · Instalar Docker en el VPS

Entra por SSH y ejecuta:

curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # correr docker sin sudo
# cierra sesión y vuelve a entrar para que aplique el grupo

Verifica: docker version y docker compose version imprimen salida.

3 · Subir el código al servidor

git clone <url-de-tu-repo> wabos
cd wabos

(O sube el proyecto con scp/rsync si el repo no está hospedado en ningún lado.)

4 · Crear y llenar el .env

cp .env.example .env
nano .env

Llena como mínimo:

VariableQué poner
APP_DOMAINapp.tudominio.com (o :80 para prueba rápida HTTP-only por IP)
ALLOWED_ORIGINhttps://app.tudominio.com
DASHBOARD_URLhttps://app.tudominio.com
POSTGRES_PASSWORDuna contraseña fuerte y aleatoria
JWT_SECRETopenssl rand -hex 32
DASHBOARD_TOKENopenssl rand -hex 24
STORE_INTERNAL_KEYopenssl rand -hex 24
WA_INTERNAL_KEYopenssl rand -hex 24
ANTHROPIC_API_KEYtu clave (recién rotada), o déjala vacía
Genera un secreto al vuelo con openssl rand -hex 32. Todo lo demás (billing, SMTP, push, R2) es opcional — déjalo vacío para desactivarlo.

5 · Lanzar

docker compose up -d --build

La primera build tarda unos minutos (instala dependencias y compila los dos apps Next). Luego revisa que todo esté sano:

docker compose ps
docker compose logs -f engine     # ver el arranque del motor; Ctrl-C para dejar de seguir
Esperado: el motor corre las migraciones e imprime WABOS engine is running. Caddy obtiene el certificado HTTPS automáticamente la primera vez que visitas el dominio.

6 · (Opcional) Cloudflare R2 para fotos de productos

R2 es el almacén de imágenes (tipo S3, de Cloudflare). Sin él, el catálogo y el import/export CSV funcionan igual — solo la subida de fotos de producto queda desactivada (el endpoint responde 503). Es gratis hasta 10 GB. Estado: apagado hasta que llenes las 5 variables de abajo.

  1. Panel de Cloudflare → R2 → Create bucket (p.ej. wabos-media).
  2. Settings → Public access: actívalo (te da una URL https://pub-xxxx.r2.dev) o conecta un dominio propio como img.tudominio.com. Copia esa URL pública (sin barra final).
  3. Manage R2 API Tokens → Create API token → permiso Object Read & Write. Anota el Access Key ID, el Secret Access Key, y tu Account ID (arriba a la derecha del panel de R2).
  4. Ponlos en .env: 
    R2_ACCOUNT_ID=...            # tu Account ID de Cloudflare
R2_ACCESS_KEY_ID=...         # del token
R2_SECRET_ACCESS_KEY=...     # del token (solo se muestra una vez)
R2_BUCKET=wabos-media        # el nombre del bucket
R2_PUBLIC_BASE_URL=https://pub-xxxx.r2.dev   # la URL pública, sin / al final
  5. Aplica los cambios recreando el motor: docker compose up -d engine.
Esperado: en Catálogo → abre un producto → Agregar foto → la imagen se sube y aparece en la lista y en Registro. El archivo queda en R2 bajo products/<negocio>/… y su URL pública se guarda en el producto.
La subida se activa al recrear el contenedor (up -d), no con restart — el motor lee las variables solo al arrancar.

7 · Crear el primer usuario

docker compose exec engine pnpm --filter @wabos/engine create-user

Sigue las indicaciones (email, contraseña, nombre del negocio). Esta es la cuenta con la que tu hermano inicia sesión en https://app.tudominio.com.

8 · Vincular WhatsApp

  1. Abre https://app.tudominio.com, inicia sesión.
  2. Ve a Conexión — aparece un código QR.
  3. En el teléfono: WhatsApp → Dispositivos vinculados → Vincular dispositivo → escanea el QR.
  4. El estado cambia a conectado. La sesión se guarda en un volumen de Docker, así que sobrevive reinicios y redespliegues.

9 · Prueba de humo (hazlas una vez, en orden)

  • Inicia sesión en el dominio por HTTPS (se ve el candado).
  • Conexión muestra conectado tras escanear.
  • Envía un WhatsApp al número vinculado desde otro teléfono → aparece en el Inbox; responde desde el inbox → llega al teléfono.
  • Catálogo → Descargar plantilla → llena 2–3 filas en Excel/Sheets → Importar CSV → aparecen los productos (revisa el toast de creados/actualizados).
  • Catálogo → Exportar → descarga el CSV y coincide con tu catálogo.
  • (Si R2 está configurado) abre un producto → Agregar foto → la imagen se ve en la lista.
  • Registro (POS): registra una venta → aparece en Ventas.
Si todas pasan, estás en vivo. 🎉

10 · Import/Export de inventario — cómo funciona (para el dueño)

  • Descargar plantilla entrega un CSV con las columnas correctas y una fila de ejemplo:
    sku, name, description, category, price, cost, currency, stock, track_stock, active.
  • Llénalo en una hoja de cálculo y usa Importar CSV. Las filas se emparejan por SKU: un SKU existente actualiza ese producto, lo demás se agrega. name y price son obligatorios; las filas con error se reportan y se saltan (el resto igual se importa).
  • Exportar descarga tu catálogo actual con la misma forma, para editarlo y reimportarlo de ida y vuelta.

11 · Operación día a día

Actualizar a una nueva versión

git pull
docker compose up -d --build

Las migraciones corren solas al arrancar el motor.

Backups (recomendado)

Pon BACKUP_DIR=/app/apps/engine/data/backups en .env y redespliega — se escribe un snapshot JSON diario de todos los datos en el volumen wa_data. Respalda también Postgres:

docker compose exec postgres pg_dump -U wabos wabos > wabos-$(date +%F).sql

Logs y reinicio

docker compose logs -f engine     # o dashboard, caddy
docker compose restart

12 · (Después) Pasar a los backends separados

Cuando quieras que la tienda y WhatsApp corran como procesos separados — para que reiniciar uno nunca toque al otro — baja el stack combinado y levanta el split (usa la misma imagen y el mismo .env):

docker compose down
docker compose -f docker-compose.split.yml up -d --build

Esto arranca store (ROLE=store) y whatsapp (ROLE=whatsapp) en vez del engine único. Comparten el mismo Postgres y el mismo volumen de sesión de WhatsApp, así que no se pierde nada y el vínculo de WhatsApp queda intacto. Para volver: docker compose -f docker-compose.split.yml down y luego docker compose up -d.

Verifica tras el cambio: envía un WhatsApp entrante (debe llegar al Inbox → funciona el puente de eventos), responde desde el inbox (debe enviarse → funciona el canal interno), y corre docker compose -f docker-compose.split.yml restart whatsapp — el dashboard/API siguen arriba todo el tiempo.

Solución de problemas

SíntomaQué revisar
Sin HTTPS / error de certificadoAsegúrate de que el DNS apunta al servidor y que los puertos 80+443 están abiertos en el firewall del VPS. Revisa docker compose logs caddy.
El dashboard carga pero las llamadas a la API fallanRevisa docker compose logs engine. El dashboard alcanza el motor por la red interna (ENGINE_ORIGIN), así que el contenedor del motor debe estar sano.
WhatsApp no conectaReabre Conexión para un QR nuevo. Si entra en bucle: docker compose restart engine y reintenta.
La carga de imagen dice "no configurado"Faltan variables R2 de §6.
Resetear la base de datos (borra todo)docker compose down -v elimina los volúmenes — hazlo solo a propósito.
